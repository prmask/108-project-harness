# Research First

## Purpose
Provide a repeatable process for researching unfamiliar technologies, APIs, libraries, scientific concepts, implementation approaches, and external dependencies before implementation.

## When to Use
Use when a technology, API, dependency, scientific/statistical method, security mechanism, browser/platform API, or integration is unfamiliar, uncertain, or potentially changed.

## Procedure
1. Define the exact research question.
2. Identify authoritative sources, preferring official documentation, specifications, primary repositories, and primary scientific sources.
3. Verify current behavior, versions, compatibility, limitations, and security implications.
4. Separate facts, recommendations, and assumptions.
5. Record important findings in `docs/research/`.
6. Return a recommendation with alternatives, risks, and implementation implications.

## Rules
- Do not rely on remembered APIs when current documentation is available.
- Do not fabricate documentation, capabilities, benchmarks, or citations.
- Research does not authorize a product or architecture change.
- Do not add a dependency merely because research identifies it.

## Output
Research question, sources, verified findings, assumptions, recommendation, risks, and implementation implications.
