# Feature Planning

## Purpose
Convert an approved request into an implementation-ready plan without silently inventing product behavior.

## Procedure
1. Read `AGENTS.md` and relevant product, experiment, and architecture documentation.
2. Clarify consequential ambiguity.
3. Identify affected user flows and screens.
4. Define behavior and acceptance criteria.
5. Identify data, domain logic, persistence, and API implications.
6. Identify experiment-integrity implications.
7. Identify UX/UI requirements and required design work.
8. Identify tests and edge cases.
9. Identify documentation and migration needs.
10. Produce a scoped implementation plan.

## Rules
- Never silently change experiment meaning.
- Separate requirements from implementation choices.
- Do not design architecture before understanding the product requirement.
- Keep scope limited to the requested outcome.

## Output
Problem, scope, user flow, acceptance criteria, data impact, architecture impact, UX impact, test plan, risks, and implementation steps.
